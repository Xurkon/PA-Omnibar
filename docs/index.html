OmniBar Developer Docs v1.3.0

This documentation provides technical details on the OmniBar codebase, specifically tailored for the Project Ascension (3.3.5a) adaptation.

📁 Project Structure

  • OmniBar.lua: Core addon logic, event handling, and initialization.
  • Options.lua: AceConfig-3.0 options table and UI generation.
  • OmniBar.xml: XML templates for frames and icons.
  • OmniBar_*.lua: Expansion-specific spell data (TBC, Wrath, etc.).

🛠️ Core API Shims

To support the 3.3.5a client with modern addon logic, several APIs have been shimmed in OmniBar.lua:

C_PvP & C_Timer

-- C_PvP Shim
C_PvP = {
    IsRatedBattleground = function() return false end
}

-- C_Timer Shim
C_Timer = {
    After = function(duration, func) ... end
}

Frame Methods

Missing frame methods like SetClipsChildren and SetSwipeColor have been proactively shimmed safely to prevent nil errors.

🔮 Spell Detection Logic

OmniBar on Ascension uses a dual-lookup system for maximum compatibility:

  1. ID Lookup: Checks addon.Cooldowns[spellID] first.
  2. Name Fallback: If ID fails, checks SPELL_ID_BY_NAME[spellName].
Note: SPELL_ID_BY_NAME is automatically built on initialization by iterating through all registered cooldowns and mapping their names. 
-- Example Fallback Logic
if (not addon.Cooldowns[spellID]) and spellName and SPELL_ID_BY_NAME[spellName] then
    spellID = SPELL_ID_BY_NAME[spellName]
end

🐛 Known Issues & Fixes

"OmniBar has already been added"

FIXED Caused by duplicate Initialize methods. Removed the custom one in favor of standard OnInitialize.

"Unknown addon chat type"

FIXED Occurs when GetDefaultCommChannel returns nil (Solo). SendVersion now guards against nil channels.

FIXED ElvUI Enhanced expected OmniBar.icons. Patched to iterate OmniBar.bars instead.
